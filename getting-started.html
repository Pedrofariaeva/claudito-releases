Getting started

Your First Project

Nine steps, in order, from an empty Claudito to a project your colleagues can open.

Takes about an hour, most of it waiting for the search You need Claudito installed, and an ORCID

Before you begin

Open a terminal and type clt. Claudito prints its version on the first line — if you are reporting a problem to Pedro, that line is the first thing he needs.

Everything below is typed at Claudito's own prompt, not in the terminal.

Create a project

type n

At the list of projects, n starts a new one. Give it a short codename — no spaces.

You should see: a confirmation naming the project, and whether it joined a team.

Create a team

type t

A team is the people you share work with. Create one and give it a name.

Why it matters: projects are shared through a team, never person to person. No team, no sharing.

Check the project is in the team

type project team

A project you create while working in a team joins it automatically, and Claudito says so when it is created. This confirms it.

If it says the project is private, put it in the team with project team <name>. A project outside a team is invisible to everyone else, and that looks exactly like broken sharing.

Invite someone

type invite

You are asked for their ORCID, then their e-mail address. Invite somebody who is not already in one of your teams — that is the case worth testing.

Tell them: a confirmation code is e-mailed to them, and it can land in spam. They should search for trackonperformance if they cannot find it.

Write the abstract

type abstract

A few lines on what the project is about. Save the file and close it.

Worth doing before the search: Claudito can search from what you have written, rather than from a query you type.

Find the papers

type harvest

Searches every database you have access to, in one pass, and removes papers that appear in more than one of them.

This takes a while. It reports how many papers it found and how many arrived with a PDF.

Look at what came back

type ref list

Then ref organise to sort the papers into the shape of your document, and screen all to judge which are relevant.

Look at the folders it created under references. That structure is what your writing will follow.

Write the project plan

type plan

Write what you intend to do. Save and close the file, then type plan again and check your text is there.

While you are in the file: format shows how to add a figure, a table or an equation without knowing LaTeX.

Leave properly

type clt

This saves your session, commits the work and uploads it. It is the step people skip.

Closing the window instead leaves everything on your own computer. Your colleagues see nothing, and it looks as though sharing is broken.

Then ask your colleague to check

They run clt. Your project should be in their list, with its contents.

If it is not, send Pedro three things: the version line from the first screen, what you typed, and a photograph of the screen. Those three make a problem findable; a description of it usually does not.

Every command here has a longer form behind help, and cheatsheet lists the ones used most. If a project ever grows past a few gigabytes, clean shows what it is carrying that it no longer needs.
