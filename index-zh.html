深入 Claudito

一个驻留在终端里的研究助手——从检索文献到产出论文，始终与你的团队保持同步。

自动更新 每次启动时 运行于 macOS · Windows · Linux 许可 专有，源码不公开 语言

Claudito 是一款免费的 CLI（命令行）学术研究工具，支持 Windows、macOS 和 Linux——本地优先，且不是 AI 智能体。它在整个研究流程中支持研究者及其团队：从 500 个出版商数据库——Springer、Elsevier、IEEE 等——检索、筛选并获取论文，在你的计算机上以干净的 BibTeX 参考文献按主题树组织一切，并通过 Git 与同事同步。最妙的是：有了 Claudito，你不再需要 LaTeX——只需写作、选择出版商，LaTeX、Word 和 PDF 文档数秒内即可就绪。（内置 LaTeX 编辑器，供需要者使用。）

大多数研究工具只解决一个环节——这里一个文献管理器，那里一个编辑器，别处一个共享网盘——让研究者在它们之间手工搬运工作。Claudito 在一个地方覆盖整个链条：检索数据库、保存参考文献、撰写文档、生成 PDF，并与项目成员共享。

它为“研究者优先”的人而造。以下任何功能都不需要懂 LaTeX、git 或云控制台。

它为何存在：为期刊重排论文格式每年耗费研究团队估计 11 亿美元的自有时间；仅生物医学领域，同行评审一年就占用了 6340 万小时；2010 至 2024 年间 Q1 期刊论文增长 +121%，而整体产出增长 84%。研究周期的 85 个流程中，58 个是机械性的——Claudito 承担这 58 个，把其余 27 个留给研究者。（AI-Assisted Tools for Academic Researchers: A Full Automation Process，预预览，2026。）

检索文献

一次性检索你有权访问的每个数据库，一遍完成，并统计实际到达的数量。好处是不用在标签页之间来回切换就能获得完整覆盖——不必在十几个界面中重复同一查询，再手工核对结果。

harvest检索所有已启用的数据库；目标数量按真实 PDF 计，而非命中数
harvest --precision在广度与相关性之间取舍：high、normal 或 low
harvest --resync在检索更多文献之前，先重新筛选已有的文献
search <query>在 100 多个数据库中检索
search related基于你已写下的内容检索，而非输入的查询词
legal harvest检索法律与法规来源
dbs查看哪些数据库已启用、待启用或缺少 API 密钥
track all保留本轮检索到的所有结果

到达即去重

同一篇论文来自四个数据库也只是一条参考文献，按 DOI 和标题相似度匹配。

中西来源兼备

CNKI、万方、VIP、Socolar，与 IEEE、Elsevier、Springer、Web of Science、JSTOR 并列。

可断点续传

采集状态会被保存，长时间运行中断后可以继续，而不必从头开始。

管好参考文献

论文会被标记、归入你实际文档的结构，并接受相关性筛选。好处是参考文献列表与论文结构一致——你始终知道每条来源属于哪一章，以及还缺什么。

ref list本项目保存的所有文献
ref organize交互式标记并分配参考文献
ref organize plan按你的计划建立章节文件夹，并把参考文献归档进去
ref organize pdf按有无 PDF 分成两组
screen all对已跟踪的参考文献做相关性筛选
allocate <doi>把一篇论文分配给你文档的某一章
ref suggest让 AI 建议每条参考文献的归属
map references显示每条引用属于哪一章
ref bib生成 citations.bib

写作无需 LaTeX

你写一份纯文本文件，Claudito 从中产出排版好的 PDF 和 Word 版本。好处是排版从不打断思考——同一来源生成两种格式，二者不可能产生分歧。

# Title
文档标题
## Section
章节标题——### 用于小节
[FIGURE: chart.png]
插入图片，居中，图片下方是 Caption: 行
[TABLE: results.csv]
把电子表格变成真正排版好的表格
[EQ: E = mc^2]
句内公式
[EQUATION: …]
带编号的独立公式
[CITE: doi]
一条引用，对照你的参考文献列表解析
- item
项目符号列表——1. 用于编号列表
// note
写给自己的备注；绝不出现在输出中

同一来源产出 PDF 与 Word

两者出自同一文本文件，因此不可能相互矛盾。

期刊模板

Elsevier 与 Springer 版式、NSFC 申请书工作区，以及会议幻灯片。

每份草稿都归档

每次编译都保留带时间戳的副本，早期版本永远可以找回。

产出成果

不止论文本身：幻灯片、基金申请书、图表和概念图，全部来自项目中已有的材料。好处是不必为每个受众重做同样的内容。

p把项目文档编译为 PDF
new slide用学校模板开始一份演示文稿
build slides把演示文稿编译为 PDF
new proposal nsfc创建 NSFC 申请书工作区
nsfc update用你的参考文献填写申请书，并列出缺口
proposal feasibility检查申请书还缺什么
diagram research生成研究思路图
export graph从 JSON 或 CSV 生成图表
export html生成项目的网页版本
export publications把筛选后的论文推送到网站

团队协作

你通过 ORCID 邀请协作者。对方安装 Claudito、回答一个问题，共享项目就会出现。好处是协作者在任何地方都无需注册账户——不需要 GitLab、不需要服务器权限、没有任何要注册的东西。下载凭证随邀请一同传递，用发送到其邮箱的验证码密封。

invite <orcid>通过 ORCID 邀请某人加入团队
t团队：创建、加入、切换，或为项目设定团队
t list你所属的团队
team invites谁已被邀请、谁已加入
team members谁真正能打开项目（从 git 托管方读取）
invite mail-log这台计算机发出的每个验证码的去向

身份即 ORCID

研究者已用于署名的同一标识符，并对照验证码发送到的邮箱核验。

所有者掌控访问权限

没有人能仅凭知道团队名称加入。邀请由所有者发出，访问权限可以在托管方真正撤销。

项目自动到达

成员一旦加入，团队项目会在其下次启动时自动下载。无需克隆，无需配置。

工作的署名

作者顺序和贡献百分比记录在项目中，并附有每个人实际所做工作的日志。好处是署名依据记录确定，而不是投稿时凭记忆争论。

authors当前记录的贡献情况
authors set P:50 T:50设定份额
authors first <name>设定第一作者
authors score数字背后的自动评分

一切都不会丢失

每个项目都是一个 git 仓库——无论你是否知道这意味着什么。提交和推送都由工具代劳。好处是任何版本都不会被覆盖——离线一天也没有任何代价，因为提交保存在本地，网络恢复后即发送。

git sync提交并推送所有内容
git pull拉取团队的最新内容
organize把散落的文件归档并整理进项目结构
pending等待批准的排队文件更新
versions项目文档的早期版本
trash <path>把文件移开——绝不直接删除
restore找回被移走的条目
status ongoing把项目标记为进行中、已完成或已归档

AI 由你选择

Ollama 在你自己的机器上运行，零成本、可离线。Kimi 和 Claude 可用你自己的密钥接入。好处是没有什么能强迫你的材料进入别人的云端，工作也不需要任何订阅。Claudito 中的模型只回答问题——筛选、分类、修改建议。它不能运行命令、调用 API 或读取你的 PDF：每个操作都由 Claudito 自己的代码执行，并且它绝不会替你写论文。

ai status当前在回答问题的是哪个模型
ai switch在 Kimi、Claude、Ollama 或自动模式之间切换
ai key设置你自己的 API 密钥
screen <doi>判断一篇论文与你问题的相关性
kimi / claude / ollama专门向某一个模型提问

单向设计

Claudito 是一个本地优先的命令行工具，不是 AI 智能体，也不是云服务。好处是你的工作只存在于你自己拥有的基础设施上——没有什么可泄露的，因为它无处可去。

不是 AI 智能体

一个本地优先的命令行工具。它只做你要求的事，且只在你要求时做——并且绝不会替你写论文。

仅下载式更新

更新只沿一个方向流动：从本发布页面到你的机器。关于你和你工作的任何信息都不会被回传。

你的内容属于你

项目只同步到你自己私有的 GitLab/Gitee 账户。Claudito 没有服务器、没有账户系统、没有遥测。

密钥属于个人

出版商和模型的 API 密钥存放在每位用户自己的机器上，绝不共享、转发或上传——即使是团队成员之间也不例外。

带论文走完同行评审

投稿、审稿意见和附信作为一轮轮记录保存在项目中，就在所属稿件旁边。好处是六个月后的重投仍然带着完整历史——问了什么、改了什么、为什么改。

review new <name>为一次投稿开启一个评审轮次
review status每次评审及其所处阶段
review note为当前轮次记录一条备注
review screen筛查论文的方法学缺陷

声明 AI 的使用方式

每个 AI 辅助操作在发生时即被记录，期刊日益要求的披露声明就根据这份日志生成。好处是一份诚实、完整的声明——依据记录写成，而非投稿时凭记忆重构。

show provenance本项目中每一个 AI 辅助操作
generate disclosure生成 AI 使用披露文档

多个项目，多重角色

每个工作区有自己的研究文件夹、自己的团队和自己的设置，一条命令即可在它们之间切换。好处是导师的项目和你自己的学位论文互不干扰，也无需安装多份。

profile你所在的工作区及你在其中的角色
profile switch切换到另一个工作区
project team <team>把项目移入某个团队——贡献者随之一同转移
project team none把项目从其团队中移出
