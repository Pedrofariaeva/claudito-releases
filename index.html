Inside Claudito

A research assistant that lives in the terminal — from finding the literature to producing the paper, with the team attached.

Current release v2.7.61 Runs on macOS · Windows · Linux Licence proprietary, source private

Most research tooling solves one slice — a reference manager here, an editor there, a shared drive somewhere else — and leaves the researcher to carry work between them by hand. Claudito covers the whole span in one place: search the databases, keep the references, write the document, produce the PDF, and share it with the people on the project.

It is built for people who are researchers first. Nothing below requires knowing LaTeX, git, or a cloud console.

Finding the literature

Searches every database you have access to at once, in one pass, and keeps count of what actually arrived. The benefit is coverage without the tab-juggling — no repeating the same query across a dozen interfaces and reconciling the results by hand.

harvestSearch every active database; targets count real PDFs, not hits
harvest --precisionTrade breadth against relevance: high, normal or low
harvest --resyncRe-screen what you already have before searching for more
search <query>Search across more than 100 databases
search relatedSearch from what you have already written, not a typed query
legal harvestSearch legal and regulatory sources
dbsWhich databases are active, on standby, or missing an API key
track allKeep every result found in this pass

Duplicates removed on arrival

The same paper from four databases is one reference, matched by DOI and title similarity.

Chinese and Western sources

CNKI, Wanfang, VIP and Socolar alongside IEEE, Elsevier, Springer, Web of Science and JSTOR.

Resumable

Harvest state is saved, so a long run that stops can carry on instead of starting over.

Keeping the references in order

Papers are tagged, sorted into the structure of your actual document, and screened for relevance. The benefit is that the reference list mirrors the paper, so you always know which chapter a source belongs to and what is still missing.

ref listEverything saved for this project
ref organizeTag and allocate references interactively
ref organize planBuild chapter folders from your plan and file references into them
ref organize pdfSplit into those with a PDF and those without
screen allScreen tracked references for relevance
allocate <doi>Assign a paper to a chapter of your document
ref suggestLet the AI propose where each reference belongs
map referencesShow which citation belongs to which chapter
ref bibGenerate citations.bib

Writing without LaTeX

You write a plain text file. Claudito produces the typeset PDF and the Word version from it. The benefit is that formatting never interrupts thinking — and the same source yields both formats, so they cannot drift apart.

# Title
The document title
## Section
A section heading — ### for subsections
[FIGURE: chart.png]
Places the image, centred, with the Caption: line beneath it
[TABLE: results.csv]
Turns the spreadsheet into a real typeset table
[EQ: E = mc^2]
An equation inside a sentence
[EQUATION: …]
A numbered display equation
[CITE: doi]
A citation, resolved against your reference list
- item
A bulleted list — 1. for numbered
// note
A comment to yourself; never appears in the output

PDF and Word from one source

Both are produced from the same text file, so the two cannot disagree.

Journal templates

Elsevier and Springer layouts, NSFC proposal workspaces, and conference slide decks.

Every draft archived

Each compile keeps a timestamped copy, so an earlier version is always recoverable.

Working as a team

You invite a collaborator by their ORCID. They install Claudito, answer one question, and the shared projects appear. The benefit is that a collaborator needs no account anywhere — no GitLab, no server access, nothing to register. The download credential travels inside the invitation, sealed with a code sent to their e-mail.

invite <orcid>Invite someone to the team by ORCID
tTeams: create, join, switch, or set a project's team
t listThe teams you belong to
team invitesWho has been invited and who has joined
team membersWho can actually open the projects, read from the git host
invite mail-logWhat happened to every code this computer sent

Identity is the ORCID

The same identifier researchers already use for authorship, verified against the e-mail it was sent to.

The owner controls access

Nobody joins by knowing a team name. Invitations come from the owner, and access can be revoked for real on the host.

Projects arrive by themselves

Once someone joins, the team's projects download on their next start. Nothing to clone or configure.

Credit for the work

Author order and contribution percentages are recorded in the project, alongside a log of what each person actually did. The benefit is that authorship is settled from a record, not from memory at submission time.

authorsContributions as they currently stand
authors set P:50 T:50Set the shares
authors first <name>Set the first author
authors scoreThe automatic scoring behind the numbers

Nothing gets lost

Every project is a git repository, whether or not you know what that means. Work is committed and pushed for you. The benefit is that no version is ever overwritten — and an offline day costs nothing, because commits are kept locally and sent when the connection returns.

git syncCommit and push everything
git pullBring down the team's latest
organizeArchive and sort loose files into the project structure
pendingQueued file updates awaiting approval
versionsEarlier versions of the project's documents
trash <path>Move a file out of the way — never deleted outright
restoreBring a trashed item back
status ongoingMark the project in progress, complete, or archived

The AI is yours to choose

Ollama runs on your own machine at no cost and works offline. Kimi and Claude are available with your own key. The benefit is that nothing forces your material into someone else's cloud, and no subscription is required to work.

ai statusWhich model is answering right now
ai switchMove between Kimi, Claude, Ollama, or automatic
ai keySet your own API key
screen <doi>Judge a paper's relevance to your question
kimi / claude / ollamaPut a question to one model specifically

Taking a paper through peer review

Submissions, reviewer comments and cover letters are kept as rounds inside the project, next to the manuscript they belong to. The benefit is that a resubmission six months later still has its history attached — what was asked, what changed, and why.

review new <name>Start a review round for a submission
review statusEvery review and the stage it has reached
review noteRecord a note against the current round
review screenScreen a paper for methodological weaknesses

Declaring how AI was used

Every AI-assisted action is logged as it happens, and the disclosure statement journals increasingly require is generated from that log. The benefit is an honest, complete declaration written from a record rather than reconstructed from memory at submission.

show provenanceEvery AI-assisted action taken in this project
generate disclosureProduce the AI-use disclosure document

Several projects, several roles

A workspace holds its own research folder, its own team and its own settings, and you move between them in one command. The benefit is that a supervisor's project and your own thesis stay separate without separate installations.

profileThe workspace you are in and your role in it
profile switchMove to another workspace
project team <team>Move a project into a team — contributors come with it
project team noneTake a project back out of its team

It looks after itself

Updates without being asked

Every start checks for a new release and installs it. Nobody is left on an old version.

Installs what it needs

Missing Git is installed for you rather than reported as an error.

Works offline

Writing, compiling and local AI need no connection. Commits are kept and sent when you are back.

Identity is protected

ORCID, e-mail and team membership are snapshotted and restored if a config is damaged.

Health check built in

clt --doctor reports what is wrong with an installation and what to do about it.

One command to install

A single line on macOS or Windows, ending inside a running Claudito.

Commands shown are those available in the project shell; type help for the full list, cheatsheet for the common ones, or features for an overview from inside Claudito. Availability depends on your role — team members see the collaboration commands, and cluster commands appear only for those with server access.
