TITLE: Your First Claudito Project
EYEBROW: Getting started
SUBTITLE: Nine steps, from a simple project to teams sync
TAKES: about 30min well dedicated, including the search, screen, edit and publish latex files
YOU NEED: Install Claudito (GitHub), your ORCID, your colleagues ORCID and email, create an account on GitLab (a GitHub account is optional)


=== BOX: Prepare 1 — install Claudito
Create a free **GitLab** account before you start, https://gitlab.com and use the same e-mail you will give in Claudito. It will be used to share your projects with the teams. A **GitHub** account is optional: Claudito lives at https://github.com/Pedrofariaeva/claudito-releases and with an account you can give it a star if you like it.


PLACE: On a Mac
Open **Terminal**: press **Cmd + Space**, type `Terminal` and press Enter. Paste this line and press Enter:
CODE: (curl -fsSL https://github.com/Pedrofariaeva/claudito-releases/releases/latest/download/claudito-macos.tar.gz -o claudito.tar.gz || curl -fsSL https://gitlab.com/Pedrofariaeva/claudito-releases/-/raw/main/claudito-macos.tar.gz -o claudito.tar.gz) && tar -xzf claudito.tar.gz && cd claudito-external-v* && ./install.sh

PLACE: On Windows
Open **PowerShell**: press the **Windows key**, type `PowerShell` and press Enter. Paste this line and press Enter:
CODE: [Net.ServicePointManager]::SecurityProtocol='Tls12'; Set-ExecutionPolicy -ExecutionPolicy Bypass -Scope Process -Force; try { irm https://github.com/Pedrofariaeva/claudito-releases/releases/latest/download/install.ps1 | iex } catch { irm https://gitlab.com/Pedrofariaeva/claudito-releases/-/raw/main/install.ps1 | iex }

END PLACES
The same one-line codes are always on GitHub: https://github.com/Pedrofariaeva/claudito-releases
WARNING: **Only in Terminal or PowerShell.** Do not use other editors
NOTE: If it says **it cannot connect,** run the same line again. It tries GitHub first and a mirror second, and a slow connection often needs a second try.


=== BOX: Prepare 2 — Setup questions

After install, Claudito asks for this information, in this order:
**Your name** (whatever you want to be called), your **ORCID** and your **e-mail** (preferably your ORCID's e-mail). Team invitations work with the ORCID number and e-mail, so type them carefully.
**Which folder is your research:** accept the folder Claudito suggests, or give the one you already have.
**Ollama**, the default AI engine Claudito uses in the backEnd: it installs automatically, is free and needs no key. We recommend it. (If it can't be installed, setup carries on and you can add it later with `setup`).
**Kimi key** (optional): For a stronger engine you can add kimi code. press Enter to skip if you don't have one.
**Claude key** (optional): For a stronger engine you can add Claude code. press Enter to skip if you don't have one.
**GitLab:** type your GitLab username. Claudito then opens GitLab in your browser with the form already filled in. Click **Create personal access token**, copy the token, and paste it back into the window.
NOTE: **Something went wrong or you skipped a question?** Setup never stops halfway. Type `setup` at the project list later to answer it.
NOTE: **Any AI in Claudito won't write papers or thesis for you, it is bounded to an ethical manifesto, in which is limit only to provide all sort of assistance and automations. For more content read at https://github.com/Pedrofariaeva/claudito/blob/master/templates/ETHICS.md**

=== BOX: Prepare 3 — check it works
Close the window, open a new **Terminal** or **PowerShell**, type `clt` and press Enter.
The first line shows your version, for example `✓ claudito v2.11.07`. If you ever report a problem, that line is the first thing Pedro needs.
NOTE: **If `clt` is not recognised,** close the window and open a new one. **If you skipped a question** during setup, type `setup` at the project list to answer it now.


=== BOX: There are two places you type. Know which one you are in.
Most confusion comes from typing a command in the wrong one.

PLACE: The project list
PROMPT: Which one? [number/n/o/q/help]:
Here you create a project (`n`), manage teams (`t`), and **open a project by typing its number**.

PLACE: Inside a project
PROMPT: [personal | myproject | Ollama] >
The prompt shows your project's name. Everything else here (invite, abstract, harvest, plan) **only works in this one**.

END PLACES
If Claudito answers **“Invalid choice”**, you are at the project list. Type your project's number, then try again.


=== STEP: Create a project
WHERE: At the project list
TYPE: `n`
Give it a short codename with no spaces. It appears in your list with a number next to it.
NOTE: **If you have no team yet,** the project is private for now. That is expected, and the next step fixes it. If you already have a team, Claudito asks which team the project is for (see **Projects and teams** below the steps).


=== STEP: Create a team, and put your project in it
WHERE: At the project list, then inside the project
TYPE: `t` then `3` type a team name, then `b` to go back
Now open your project by typing its number, and put it in the team:
TYPE: `project team your-team-name`
WARNING: **Don't skip the second part.** Creating a team does not move a project you already made into it. Without this, your colleague joins an empty team, and it looks exactly like sharing is broken.


=== STEP: Invite a member
WHERE: Inside the project
TYPE: `invite`
Claudito asks for their ORCID, shows you the name it found so you can confirm it is the right person, then asks for their e-mail address.
Invite someone who is **not** already in one of your teams. That is the case worth testing.
NOTE: **Tell them:** they will get an e-mail with a code, and it can land in spam. If they cannot find it, they should search for `trackonperformance`.


=== STEP: Write an abstract
WHERE: Inside the project
TYPE: `abstract`
A file opens. Write a few lines on what the project is about, then save and close the file.
NOTE: **Why first:** the search in the next step reads this to know what to look for.


=== STEP: Search for the bibliography
WHERE: Inside the project
TYPE: `harvest`
Claudito shows a numbered list of documents it can search from, and asks which one to use.
WARNING: **Type the number next to `abstract.txt`. Don't just press Enter.** Option 1 is the empty plan template, and the search would look for its placeholder questions instead of your topic.
NOTE: **This takes a while.** It searches every database you can reach, removes duplicates, and reports how many papers it found and how many came with a PDF.


=== STEP: Explore help
WHERE: Inside the project
TYPE: `help` or `cheatsheet`
`help` lists every command, grouped by what it does. `cheatsheet` shows only the ones used most.
Try one or two that look useful. This is how you learn the rest.


=== STEP: Check the references, then write your project plan
WHERE: Inside the project
TYPE: `ref list` then `ref organise` then `plan`
`ref list` shows the papers the search found. `ref organise` sorts them into folders under `references`. That folder structure is the shape your document will follow.
Look at those folders, then type `plan` and write what you intend to do, following that structure.
NOTE: **Optional:** `screen all` has the AI judge which papers are actually relevant. It is slow on a large search.


=== STEP: Close the plan, check it saved, and leave properly
WHERE: Inside the project
TYPE: `plan` then, when finished `clt`
Save and close the plan file. Type `plan` again and check your text is still there.
To add a figure, table or equation without knowing LaTeX, close the file first and type `format` at the Claudito prompt. It won't work typed inside the file itself.
WARNING: **Leave with `clt`, never by closing the window.** `clt` saves your work and uploads it. Closing the window keeps everything on your own computer, and your colleague sees nothing.


=== STEP: Check your colleague has the project
WHERE: On your colleague's computer
THEY TYPE: `clt`
Your project should be in their project list, with its contents: the abstract, the references and your plan.


=== BOX: Projects and teams
Which team a new project joins:

PLACE: No team yet
The project is private. Only you can see it.

PLACE: One or more teams
Claudito asks **“Which team is this project for?”** Type the team's number, or choose **No team — keep it to myself** to work solo.

END PLACES
**To add a project to a team later,** open it and type `project team team-name`. The same command moves a project to another team.
**To take a project out of its team,** open it and type `project team none`. It stops being shared from then on; colleagues who already downloaded it keep their copy.
NOTE: **To see your teams,** type `t` and then `1`. The project list shows each project's team after its name, like `@aonipepe`.


=== BOX: If something doesn't work
Send Pedro three things: **the version line** from the first screen, **what you typed**, and **a photo of the screen**.
Those three make a problem findable. A description on its own usually doesn't.


=== FOOTER
**help** lists every command, and **cheatsheet** lists the ones used most. If a project ever grows past a few gigabytes, **clean** shows what it is carrying that it no longer needs.
